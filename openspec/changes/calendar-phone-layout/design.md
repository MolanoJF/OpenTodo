# Design
Use a calendar-specific phone header that registers the same shell page-bar actions and reuses the existing range/navigation controls. Remove add-button bottom padding only for calendar routes; retain safe tab-bar space and scroller end clearance so the final item can be reached above the floating button. Use native details/summary rows for the phone event schedule and optional settings, backed by the existing controlled fields. Keep summary values visible and preserve native date/time inputs, read-only/provider messages and validation. The header submit button targets the existing form by a generated id; all submissions still use the current save path. No dependencies, data migrations or provider API changes. Verify 320/390/430 px, short viewports, light/dark themes, field expansion, save, dirty-close, keyboard changes and desktop. Preserve bundle budgets and measure the result.

Measured build: 143.4 KB entry / 692.4 KB first load against the prior 143.4 / 692.6 KB. The optional event UI remains in the event editor chunk; CSS handles calendar-only bottom padding without new shell JavaScript. No budget increases.
